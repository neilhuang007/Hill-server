# Individual student map downloads

This is an **opt-in** Java-world export service. It is disabled unless both export path and public URL are configured. It does not package a running world, add client mods, authenticate browser users separately, or replace the existing gallery/password-protected static campus ZIP. Do not tell students `/download` works until the proxy and a vetted export have been installed and verified.

## Stage and approve a copy

1. Offline, copy an **approved, frozen** campus-world snapshot into a dedicated operator-owned directory outside server world directories. Never set the source to `world`, `hill_campus`, a live save, a player save, or a server backup. Use a private export location not writable by Minecraft players or the web service. Preserve the original world separately.
2. Sanitize the copy **before enabling downloads**. Remove `playerdata`, `advancements`, `stats`, server config, private plugin data, backup artifacts, chat/log data, scoreboard identities, usernames/UUIDs in NBT, and confidential map contents. Inspect any map/structure/entity NBT for personal data. A `level.dat` with a `Player` NBT tag is rejected automatically, as are private files and unexpected root paths; this is only a safety check, **not** a comprehensive privacy audit. The export must contain `level.dat` and may contain only `region`, `entities`, `poi`, `DIM-1`, `DIM1`, `dimensions`, and `datapacks` at the root. Its archive has `world/` as the world folder. Real generated worlds may need additional conscious sanitization and preparation for this allowlist; never weaken it to accept an unreviewed world.
3. Keep permissions restricted on the export and plugin data directory. Put the approved source outside `/opt/hill175` because the normal installer recursively assigns that runtime to the game service account. For example, use root-owned `/opt/hill175-exports/student-campus`, give the `hill175` group read/traverse access, and keep group write disabled. The worker reads files while assembling each ZIP, so replace exports by a separate, atomic, reviewed release procedure rather than editing the directory in place. The output ZIP is checked for size/count and inspected for symlinks and private path names, but content privacy remains an operator responsibility.

## Enable

Set in `/etc/hill175/hill175.env` (never in Git):

```text
HILL175_GALLERY_PUBLIC_URL=https://builds.example.org
HILL175_STUDENT_DOWNLOAD_EXPORT=/opt/hill175-exports/student-campus
HILL175_STUDENT_DOWNLOAD_URL=https://builds.example.org/student-map/
HILL175_STUDENT_DOWNLOAD_PORT=8791
```

`EXPORT` must be an absolute directory with a prepared world; `URL` must be HTTPS, share the origin of `HILL175_GALLERY_PUBLIC_URL`, and end exactly in `/student-map/`, without query/fragment; port defaults to `8791` and must not conflict with gallery/auth/Bedrock services. Both required keys absent means disabled, and setting only one is a configuration error. The plugin already wires `/download` to the existing authenticated player identity in either development-login or Microsoft mode and closes the service on shutdown. Deploy and restart normally after setting the environment; the command does not accept player names or an unauthenticated sender.

Normal deployment configures the `/student-map/` Cloudflare + nginx reverse-proxy location to `127.0.0.1:8791` when these settings are enabled, with unchanged paths, disabled nginx access logs and disabled proxy buffering/caching. Confirm this in the rendered nginx config; do not permit direct external access to the origin. Set an explicit Cloudflare cache bypass and disable Cloudflare request-path logs, analytics and traces for this location, because URL paths contain bearer tokens. Do not put tokens in query strings, referrers, analytics, support tickets or screenshots. Enforce valid origin TLS and Cloudflare Authenticated Origin Pulls and restrict ingress as described in `docs/operations/deployment.md`. Headers supplied by the service include `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, and `X-Robots-Tag: noindex`. A leaked URL remains usable by its holder until expiry.

**Legacy bypass:** The pre-existing gallery still exposes `/download/` and password-protected `/downloads/hill-campus.zip`, which provides the same unmarked static campus export if it remains staged. Normal deployment denies `/downloads/hill-campus.zip` in the proxy when individualized downloads are enabled. If the policy is **all map downloads are individualized/fingerprinted**, also remove the old gallery static ZIP from staged gallery assets and deny or retire `/download/` as appropriate in coordinated gallery work. Check any old CDN caches/direct links. This download module does not edit gallery or its separate public website policy; leaving that ZIP accessible bypasses attribution.

## Behavior and limits

An authenticated `/download` returns a clickable, random bearer link. The linked page and ZIP require the same bearer; a ZIP is produced asynchronously from the approved directory only, not from the live campus or student files. Refresh the page while preparation finishes. Each link expires **15 minutes after issuance**, including while streaming: the service checks before every ZIP chunk (up to 64 KiB) and schedules the HTTP exchange to close at the expiry deadline, including stalled transfers. Bytes already buffered by the network may arrive later. Expired/partial ZIPs must be discarded. Download from a fresh link for slow transfers. Up to three new links per UUID per hour, one live link per UUID, 64 active links, two concurrent archive builders and a bounded 64-task queue; each world has a 2 GiB uncompressed input cap, 512 MiB per file, 30,000 file cap and 32 MiB parsed `level.dat` cap. Archive construction checks for free space equal to twice the approved input size plus 1 GiB, allowing headroom for both builders. Monitor shared disk usage and plan space for simultaneous ZIP files; unrelated server writes can still exhaust disk and failed builds require operator attention. Temporary ZIPs are private in the plugin data `student-downloads/` directory, purged after expiration or restart, with periodic cleanup. A process restart invalidates outstanding links.

Each ZIP contains a random **opaque copy fingerprint** and a SHA-256 digest over the staged map file names, sizes and bytes (not the individualized marker) in both its ZIP comment and `world/.hill175-copy.txt`. This map digest binds a download to the actual version of the staged export read during assembly; the ZIP itself has a different SHA-256 because each copy has a unique fingerprint. A restricted `student-downloads/fingerprints.tsv` logs issuance time, authenticated game UUID and fingerprint. The companion `student-downloads/transfers.tsv` records UTC timestamp, event (`ISSUED`, `READY`, `BUILD_FAILED`, `STARTED`, `COMPLETED`, `LINK_EXPIRED`, `EXPIRED`, `DISCONNECTED`), issuing UUID, fingerprint, map digest (or `PENDING` before build), and bytes written. There are no bearer tokens, browser identity or IP addresses in these records. `STARTED` is persisted and flushed before ZIP bytes are sent; `COMPLETED` means the server wrote/flushed the ZIP response bytes, **not** that the recipient's computer saved the file. `LINK_EXPIRED` is the periodic invalidation of an issued link, while `EXPIRED` means a running transfer reached expiry; link expiration may be logged up to a minute after the 15-minute access cutoff. An unfinished `STARTED` without an outcome after crash or audit/disk failure is uncertain and must not be counted as a completed transfer. Missing/writable-failed audit denies issuing new links or starting unaudited streams. Audit files fail closed at 64 MiB each. Before starting a transfer, the audit reserves space within that cap for its outcome, preventing unrelated log entries from consuming that space. Physical disk or hardware failure can still leave an uncertain outcome, and a failed outcome write raises an operator error. After securing a copy, rotate offline under an approved school privacy/retention policy before resuming downloads. Do not delete the old audit without preservation and authorization; restrict staff access to these student-linked records. For an incident, verify fingerprint and map digest from the intact ZIP comment and marker, match the fingerprint to issuance **and transfer** entries, and independently investigate export chain and identity/session evidence. **Markers can be removed or copied, and a student can share a link or ZIP: this is not cryptographic watermarking, proof of authorship, or proof of guilt.** Logs identify the UUID that requested the link, not which person/browser actually used it. The link is not bound to a browser/IP; avoid punitive action based solely on a fingerprint.

Before rollout, test with a dummy account and dummy sanitized export, confirm auth denial, correct ZIP and marker, proxy no-cache/no-referrer/no access-path logging, expiration, safe storage permissions, restart invalidation, and that the legacy static ZIP is unavailable if individualized downloads are mandatory. No external deployment is performed by this change.
