# Structure NBT to Paper world import research

Research date: 2026-08-25

Scope: whether `structure.nbt` can be turned into a playable Paper world, with emphasis on vanilla structure limits, Paper world creation, FAWE/WorldEdit import paths, `DataVersion 3955`, and the `suspicious_gravel_0..3` / `suspicious_sand_0..3` palette entries.

## Bottom line

- Yes, this can become a playable Paper world, but not as a straight vanilla Structure Block import. Local inspection shows `size=[1750,169,1754]` with about `5,092,841` explicit placed blocks and `0` entities, while Java Structure Blocks are limited to `48×48×48` and ±48 relative offsets. Sources: local file [`structure.nbt`](../../structure.nbt), [Minecraft Wiki: Structure Block](https://minecraft.wiki/w/Structure_Block).
- The safest implementation path is: (1) normalize invalid palette IDs, (2) create/load a staging Paper world with `Server#createWorld(WorldCreator)`, (3) stream the sparse block list through a custom FAWE-backed or chunked importer, then (4) save and ship the finished world folder. Sources: [Paper Javadocs: `Server#createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)), [FAWE API usage](https://intellectualsites.gitbook.io/fastasyncworldedit/api/api-usage).

## Facts

- Local inspection of [`structure.nbt`](../../structure.nbt) shows root keys `DataVersion`, `size`, `palette`, `blocks`, and `entities`; `DataVersion=3955`; `size=[1750,169,1754]`; `palette_count=185`; `block_count=5,092,841`; and `entity_count=0`.
- Vanilla structure files are NBT structure templates used by Structure Blocks and can also be placed with `/place template`. Source: [Minecraft Wiki: Structure file](https://minecraft.wiki/w/Structure_file).
- Java Structure Blocks are limited to `48×48×48`, and their relative position fields are limited to `-48..48`. Source: [Minecraft Wiki: Structure Block](https://minecraft.wiki/w/Structure_Block).
- Paper exposes `Server#createWorld(WorldCreator)` for world create/load and `Server#unloadWorld(World, boolean)` for unload/save lifecycle control. Sources: [Paper Javadocs: `Server#createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)), [Paper Javadocs: `Server#unloadWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)).
- WorldEdit’s public clipboard examples are schematic/clipboard oriented, and WorldEdit’s built-in clipboard formats are `MCEDIT_SCHEMATIC`, `SPONGE_V1_SCHEMATIC`, `SPONGE_V2_SCHEMATIC`, and `SPONGE_V3_SCHEMATIC`; there is no built-in vanilla structure-template `.nbt` format in that enum. Sources: [WorldEdit clipboard examples](https://worldedit.enginehub.org/en/latest/api/examples/clipboard/), [WorldEdit `BuiltInClipboardFormat.java`](https://github.com/EngineHub/WorldEdit/blob/master/worldedit-core/src/main/java/com/sk89q/worldedit/extent/clipboard/io/BuiltInClipboardFormat.java#L52-L203).
- FAWE extends WorldEdit with additional formats, including Minecraft Structure files. That makes a direct `.nbt` load possible in principle, but it does not remove the memory risk of representing this file's `518,745,500`-cell bounding box as a clipboard. Source: [FAWE repository: features](https://github.com/IntellectualSites/FastAsyncWorldEdit#features).
- FAWE says the WorldEdit documentation widely applies to FAWE, recommends completing FAWE operations asynchronously, and notes that `Operations.complete(...)` and `EditSession#close` are blocking. Source: [FAWE API usage](https://intellectualsites.gitbook.io/fastasyncworldedit/api/api-usage).
- `DataVersion 3955` matches Mojang’s official `world_version` for **1.21.1**, not 1.20.6. I verified this by inspecting the embedded `version.json` inside Mojang’s official server jars: the official 1.21.1 server jar reports `world_version: 3955`, while the official 1.20.6 server jar reports `world_version: 3839`. Sources: [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar), [1.20.6 metadata JSON](https://piston-meta.mojang.com/v1/packages/05d2fcbc2babf01114142c5b576a3962d00c45d6/1.20.6.json), [1.20.6 server.jar](https://piston-data.mojang.com/v1/objects/145ff0858209bcfc164859ba735d4199aafa1eea/server.jar).
- The file’s palette contains 8 synthetic IDs: `minecraft:suspicious_gravel_0..3` and `minecraft:suspicious_sand_0..3`. Local inspection shows those entries affect `73,326` placed blocks. Source: local file [`structure.nbt`](../../structure.nbt).
- Those are not canonical 1.21.1 block IDs. In Mojang’s official 1.21.1 server data, `data/minecraft/tags/block/mineable/shovel.json` lists `minecraft:suspicious_gravel` and `minecraft:suspicious_sand`, `data/minecraft/loot_table/blocks/suspicious_gravel.json` uses `minecraft:blocks/suspicious_gravel`, and archaeology processor JSONs output `Name: minecraft:suspicious_gravel` with `Properties: { "dusted": "0" }`. Sources: [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar).
- Inference from the official 1.21.1 data: the `_0..3` suffixes likely encode the `dusted` block state and must be converted back to canonical IDs plus properties before import.

## Recommended implementation

1. **Normalize the palette first.**
   - Map `minecraft:suspicious_gravel_N` → `minecraft:suspicious_gravel` plus `Properties.dusted=N`.
   - Map `minecraft:suspicious_sand_N` → `minecraft:suspicious_sand` plus `Properties.dusted=N`.
   - This mapping is an inference from Mojang’s canonical unsuffixed IDs and official `dusted` property usage in 1.21.1 server data. Sources: [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar).
2. **Target the 1.21.1 data line first.**
   - The file’s `DataVersion=3955` matches Mojang’s official 1.21.1 `world_version`, so the lowest-risk target is Paper 1.21.1 or a later 1.21.x Paper build. This is an inference from the official Mojang version metadata and server jars. Sources: [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar).
3. **Use a sparse importer rather than converting the whole bounding box to a dense clipboard.**
   - Parse the vanilla structure NBT, normalize each palette entry, and feed only the `5,092,841` explicit blocks into a FAWE `EditSession` or a rate-limited Paper importer. This avoids allocating block data for the roughly `518.7 million` cells in the bounding box. Sources: local file [`structure.nbt`](../../structure.nbt), [FAWE API usage](https://intellectualsites.gitbook.io/fastasyncworldedit/api/api-usage), [Paper Javadocs: `Server#createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)).
   - A direct FAWE Minecraft-structure load is worth testing after normalization, but should not be the only path because clipboard materialization may be much larger than the sparse input. Source: [FAWE repository: features](https://github.com/IntellectualSites/FastAsyncWorldEdit#features).
4. **Do not try to place this as one big synchronous live import.**
   - FAWE’s docs are explicit that blocking completions can block the main thread. A custom importer should likewise be chunked and rate-limited; that is an inference from the file’s scale and FAWE’s blocking guidance. Source: [FAWE API usage](https://intellectualsites.gitbook.io/fastasyncworldedit/api/api-usage).
5. **Import once into an offline/staging world, save it, then run the saved world as the playable map.**
   - This recommendation follows from the file’s size, Paper’s normal world lifecycle APIs, and the fact that the structure is sparse but still millions of placed blocks. Sources: local file [`structure.nbt`](../../structure.nbt), [Paper Javadocs: `Server#createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)), [Paper Javadocs: `Server#unloadWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)).

## Practical answer

- **Can it become a playable Paper world?** Yes.
- **Can it be used as-is via vanilla Structure Blocks?** No; the structure-block UI limits are far smaller than this file’s dimensions. Sources: local file [`structure.nbt`](../../structure.nbt), [Minecraft Wiki: Structure Block](https://minecraft.wiki/w/Structure_Block).
- **Can WorldEdit/FAWE load this exact vanilla `structure.nbt` directly?** WorldEdit itself does not expose that built-in format, while FAWE adds Minecraft Structure support. For this unusually sparse `1750×169×1754` file, a custom sparse FAWE importer is still safer than relying on a giant clipboard. Sources: [WorldEdit `BuiltInClipboardFormat.java`](https://github.com/EngineHub/WorldEdit/blob/master/worldedit-core/src/main/java/com/sk89q/worldedit/extent/clipboard/io/BuiltInClipboardFormat.java#L52-L203), [FAWE repository: features](https://github.com/IntellectualSites/FastAsyncWorldEdit#features), local file [`structure.nbt`](../../structure.nbt).
- **Is `DataVersion 3955` compatible with Paper?** Yes, if you target the 1.21.1-era data line; the official Mojang 1.21.1 server jar is the match for `3955`. Sources: [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar).
- **Are `suspicious_gravel_0..3` / `suspicious_sand_0..3` valid block IDs?** No. Normalize them to canonical IDs plus block-state properties before import. Sources: local file [`structure.nbt`](../../structure.nbt), [1.21.1 metadata JSON](https://piston-meta.mojang.com/v1/packages/7d538f57bd7f3d0638755fa605a432494e736db3/1.21.1.json), [1.21.1 server.jar](https://piston-data.mojang.com/v1/objects/59353fb40c36d304f2035d51e7d6e6baa98dc05c/server.jar).
