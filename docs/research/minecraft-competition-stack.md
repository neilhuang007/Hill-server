# Hill 175 Minecraft competition stack research

Research date: 2026-08-26

Scope: current primary-source research for the Hill 175 Minecraft competition implementation: Paper/Velocity/offline-mode implications, Paper Dialog API, PlotSquared/WorldGuard/WorldEdit-or-FAWE/Multiverse/Citizens/LuckPerms/CoreProtect, private world cloning, dedicated capture-client feasibility, Microsoft/Hill browser identity linking, Minecraft client redistribution/EULA constraints, and map generation/sourcing options including Arnis and WorldPainter.

## Facts

### Paper, Velocity, and offline-mode implications

- Paper requires Java 25 for the 26.1+ line, while Paper's Java compatibility table lists Java 21 for 1.20 through 1.21.11. Source: [Paper getting started: requirements](https://docs.papermc.io/paper/getting-started/#requirements).
- Paper's `server.properties` reference lists `online-mode=true` as the default and states that when `online-mode` is true, the server checks connecting players against Minecraft's account database, requires a valid Minecraft account, and prevents cracked players from connecting. Source: [Paper `server.properties`: `online-mode`](https://docs.papermc.io/paper/reference/server-properties/#online-mode).
- Paper's `server.properties` reference lists `log-ips=true` as the default and states that the property controls server IP logging but does not prevent plugins from logging player IP addresses. Source: [Paper `server.properties`: `log-ips`](https://docs.papermc.io/paper/reference/server-properties/#log-ips).
- Velocity can forward player IP addresses, UUIDs, and skins to backend servers. Source: [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-player-information-forwarding).
- Velocity supports three player-information forwarding formats: modern forwarding, legacy BungeeCord forwarding, and BungeeGuard. Source: [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-player-information-forwarding).
- Velocity documentation says modern forwarding is a Velocity-native binary format, uses a MAC code to make proxy impersonation harder, and is only available for Minecraft 1.13 or newer. Source: [Velocity modern forwarding](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-modern-forwarding).
- Velocity documentation says only one forwarding format can be used at a time and recommends modern forwarding for Minecraft 1.13+ client support. Source: [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-player-information-forwarding).
- For Paper behind Velocity modern forwarding, Velocity documentation says to disable `online-mode` in `server.properties` so the backend does not authenticate players because the proxy authenticates instead. Source: [Velocity modern forwarding for Paper](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-modern-forwarding-for-paper).
- For Paper behind Velocity modern forwarding, Velocity documentation says to enable `proxies.velocity.enabled`, configure `proxies.velocity.secret` to match Velocity's `forwarding.secret`, and set `proxies.velocity.online-mode` to match Velocity's `online-mode`. Source: [Velocity modern forwarding for Paper](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-modern-forwarding-for-paper).
- Velocity's security guide says backend servers are put in offline mode as part of Velocity setup, that this makes player impersonation theoretically possible, and that only the proxy should be able to connect to backend servers. Source: [Velocity security overview](https://docs.papermc.io/velocity/security/#securing-your-servers).
- Velocity's security guide strongly recommends operating-system firewalls for proxy setups. Source: [Velocity security: firewalls](https://docs.papermc.io/velocity/security/#operating-system-firewalls).
- Velocity's security guide says modern forwarding is not a replacement for a firewall. Source: [Velocity security: modern forwarding](https://docs.papermc.io/velocity/security/#velocity-modern-forwarding).

### Paper Dialog API

- Minecraft dialogs were added in Minecraft 1.21.6, and Paper released a developer API for custom dialogs in 1.21.7. Source: [Paper Dialog API overview](https://docs.papermc.io/paper/dev/dialogs/#dialog-api).
- Paper's Dialog API page is written for version 1.21.8 and warns that mentioned features or APIs may be missing or incomplete in older versions. Source: [Paper Dialog API version note](https://docs.papermc.io/paper/dev/dialogs/#dialog-api).
- Paper dialogs are server-sent custom in-game menus that can display information and gather user input. Source: [Paper Dialog API: What is a dialog?](https://docs.papermc.io/paper/dev/dialogs/#what-is-a-dialog).
- Paper dialogs can be shown during the configuration phase or during normal gameplay. Source: [Paper Dialog API: What is a dialog?](https://docs.papermc.io/paper/dev/dialogs/#what-is-a-dialog).
- Paper's Dialog API documentation includes an example for blocking players from joining until a confirmation response is received. Source: [Paper Dialog API: blocking confirmation dialog](https://docs.papermc.io/paper/dev/dialogs/#example-a-blocking-confirmation-dialog).
- Paper's Dialog API documentation includes an example for retrieving and parsing user input from a dialog response. Source: [Paper Dialog API: retrieving and parsing user input](https://docs.papermc.io/paper/dev/dialogs/#example-retrieving-and-parsing-user-input).

- LuckPerms has a developer API for reading and modifying LuckPerms data from other plugins. Source: [LuckPerms Developer API](https://luckperms.net/wiki/Developer-API).

### Private world cloning and world lifecycle

- Bukkit/Paper exposes `Server#createWorld(WorldCreator)` for creating/loading worlds. Source: [Paper Javadocs: `Server#createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)).
- Bukkit/Paper exposes `Server#unloadWorld(World, boolean)` and documents that the `save` parameter controls whether chunks are saved before unload. Source: [Paper Javadocs: `Server#unloadWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)).
- Paper Javadocs warn that unloading/loading worlds mid-tick may have side effects and recommend checking `Bukkit.isTickingWorlds()`. Source: [Paper Javadocs: `Server#unloadWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)).
- Slime-World-Manager command documentation includes `/swm clone <template-world> <world> [new-data-source]`, which creates a copy of a template world. Source: [Slime-World-Manager command docs](https://github.com/cijaaimee/Slime-World-Manager/blob/develop/.docs/usage/commands-and-permissions.md).
- InfernalSuite describes AdvancedSlimePaper as a Paper/Purpur/Pufferfish fork adding a custom world format suitable for smaller worlds such as minigame maps or per-player worlds. Source: [InfernalSuite home](https://infernalsuite.com/).
- The public Advanced-Slime-World-Manager Spigot page says Advanced SlimeWorldManager is a fork of the original Slime World Manager intended for an enhanced API and updates. Source: [Advanced SlimeWorldManager Spigot resource](https://www.spigotmc.org/resources/advanced-slimeworldmanager.87209/).

### Dedicated capture-client and render feasibility

- A Paper plugin has no documented API for reading a player's local framebuffer or screenshot pixels; Paper's relevant user-interface APIs cover server-sent dialogs and server/game state, not client framebuffer capture. Source: [Paper Dialog API](https://docs.papermc.io/paper/dev/dialogs/) and [Paper API guide](https://docs.papermc.io/paper/dev/api/).
- BlueMap is a Minecraft map renderer with a web app, and its webapp configuration supports a `start-location` expressed as the webapp URL anchor. Source: [BlueMap webapp config](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/configs/Webapp.md#start-location).
- BlueMap markers can be configured manually or through a third-party plugin using BlueMap's API, and marker positions use x/y/z coordinates. Source: [BlueMap markers documentation](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/customization/Markers.md).
- Prismarine Viewer is a web-based viewer for servers and bots. Source: [Prismarine Viewer GitHub README](https://github.com/PrismarineJS/prismarine-viewer).
- Prismarine Viewer provides a Mineflayer mode that serves a webserver to visualize a bot's surroundings in first or third person. Source: [Prismarine Viewer README: mineflayer mode](https://github.com/PrismarineJS/prismarine-viewer#mineflayer).
- Prismarine Viewer provides a `headless` mode that renders the bot view and streams it to a file or TCP target, with width, height, frame count, and view-distance options. Source: [Prismarine Viewer README: headless](https://github.com/PrismarineJS/prismarine-viewer#headless).
- Mineflayer's API documents `mineflayer.createBot(options)` and identifies the bot's client as an instance of `node-minecraft-protocol` unless supplied by the caller. Source: [Mineflayer API docs](https://github.com/PrismarineJS/mineflayer/blob/master/docs/api.md).
- ReplayStudio's README describes replay files as packet dumps from a Minecraft server to a Minecraft client and lists features for loading, saving, cutting, concatenating, and filtering replays. Source: [ReplayStudio GitHub README](https://github.com/ReplayMod/ReplayStudio).
- ReplayMod's README describes ReplayMod as a Minecraft mod for recording game sessions and replaying them from any perspective. Source: [ReplayMod GitHub README](https://github.com/replaymod/replaymod).

### Microsoft/Hill browser identity linking

- Microsoft identity platform supports OAuth 2.0 and OpenID Connect 1.0 standard implementations. Source: [Microsoft identity platform protocols](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols).
- Microsoft documentation says authorization code flow paired with PKCE and OIDC can obtain access tokens and ID tokens for supported app types. Source: [Microsoft authorization code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow).
- Microsoft's access-token claims reference states that `tid` represents the tenant and that `oid` allows applications to correlate principals; it also says `tid` should be considered with other claims in authorization decisions. Source: [Microsoft access-token claims reference](https://learn.microsoft.com/en-us/entra/identity-platform/access-token-claims-reference).
- Microsoft documentation says ROPC is incompatible with MFA. Source: [Microsoft mandatory MFA planning](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication#applications-using-resource-owner-password-credential-ropc).
- Microsoft documentation says device code flow is a high-risk authentication method that can be part of a phishing attack or used to access corporate resources from unmanaged devices. Source: [Microsoft Conditional Access authentication flows](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-authentication-flows#device-code-flow).
- Microsoft Conditional Access can explicitly target device code flow. Source: [Microsoft Conditional Access authentication flows](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-authentication-flows).

## Recommendations

### Server topology

- Use Velocity as the only public Minecraft endpoint and keep Paper backend ports private. This recommendation follows from Velocity's warning that offline-mode backends can be impersonated if anything besides the proxy can connect, and from Velocity's recommendation to use firewalls with proxy setups. Sources: [Velocity security overview](https://docs.papermc.io/velocity/security/#securing-your-servers), [Velocity firewalls](https://docs.papermc.io/velocity/security/#operating-system-firewalls).
- Use Velocity modern forwarding if all supported clients are Minecraft 1.13 or newer. This recommendation follows from Velocity's statement that modern forwarding is more secure than legacy forwarding and its recommendation to use modern forwarding for 1.13+ clients. Source: [Velocity player information forwarding](https://docs.papermc.io/velocity/player-information-forwarding/#configuring-player-information-forwarding).
- If the competition intentionally uses `online-mode=false`, treat Minecraft usernames and offline UUIDs as untrusted until the Hill175 authentication plugin has validated a `/login` or `/register` session. This recommendation follows from Paper's description of `online-mode=true` as the account-database validation boundary and Velocity's warning about impersonation risk on offline-mode backends. Sources: [Paper `online-mode`](https://docs.papermc.io/paper/reference/server-properties/#online-mode), [Velocity security overview](https://docs.papermc.io/velocity/security/#securing-your-servers).
- Pin exact versions of Paper, Velocity, and every plugin for the launch window. This recommendation follows from Paper's documented version-specific Java requirements and Dialog API version notes. Sources: [Paper requirements](https://docs.papermc.io/paper/getting-started/#requirements), [Paper Dialog API version note](https://docs.papermc.io/paper/dev/dialogs/#dialog-api).

### Login and identity

- Implement `/register <username> <password> <repeatPassword>` and `/login <password>` as commands whose contents are not broadcast to public chat; do not implement password entry via normal chat messages. This recommendation follows from the need to avoid exposing secrets and from the fact that Bukkit/Paper command handling is separate from normal chat. Source for command/API context: [Paper Command API](https://docs.papermc.io/paper/dev/command-api/basics/introduction/).
- Make registration incomplete until the browser identity-linking flow succeeds. This recommendation follows from Microsoft's support for browser-based OAuth/OIDC and from the user's stated requirement that registration cannot succeed unless linked to school identity. Source: [Microsoft identity platform protocols](https://learn.microsoft.com/en-us/entra/identity-platform/v2-protocols).
- Use authorization-code flow with PKCE/OIDC for the browser link when Hill uses Microsoft Entra ID. This recommendation follows from Microsoft's documented use of auth-code flow with PKCE and OIDC to obtain ID tokens and access tokens. Source: [Microsoft authorization code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow).
- Store the school identity key separately from the Minecraft login handle and use `tid` plus `oid` as the stable Microsoft Entra identity key if Entra is selected. This recommendation follows from Microsoft's claim guidance for `tid` and `oid`. Source: [Microsoft access-token claims reference](https://learn.microsoft.com/en-us/entra/identity-platform/access-token-claims-reference).
- Do not use ROPC/password-grant with Microsoft Entra for school login. This recommendation follows from Microsoft's statement that ROPC is incompatible with MFA. Source: [Microsoft mandatory MFA planning](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication#applications-using-resource-owner-password-credential-ropc).
- Treat device-code flow as a fallback that requires Hill IT approval. This recommendation follows from Microsoft's statement that device-code flow is high risk and can be controlled by Conditional Access. Sources: [Microsoft Conditional Access authentication flows](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-authentication-flows), [Microsoft device-code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code).
- Hash competition passwords server-side with a memory-hard password hash, rate-limit login attempts, and never store plaintext passwords locally or server-side. This is a security recommendation; the factual basis is that offline-mode usernames are not externally authenticated by Paper when `online-mode` is disabled. Source: [Paper `online-mode`](https://docs.papermc.io/paper/reference/server-properties/#online-mode).

### In-game UI

- Use Paper Dialog API for post-login category explanations, confirmations, profile text entry, and submission forms only if the pinned server/client version supports the required Dialog features. This recommendation follows from Paper's Dialog API version note and input examples. Sources: [Paper Dialog API version note](https://docs.papermc.io/paper/dev/dialogs/#dialog-api), [Paper Dialog API input example](https://docs.papermc.io/paper/dev/dialogs/#example-retrieving-and-parsing-user-input).
- Keep `/login` and `/register` as command fallbacks even if Dialog API is used for richer UI. This recommendation follows from Dialog API's version-sensitive status and the user's required launcher flow. Source: [Paper Dialog API version note](https://docs.papermc.io/paper/dev/dialogs/#dialog-api).

### Build-space architecture

- Use PlotSquared for Journey and Place build ownership because the proposal requires protected plots, visitor access, reset, and per-entry management, and PlotSquared is specifically a plot-management plugin with API integration and membership tiers. Sources: [PlotSquared API documentation](https://intellectualsites.gitbook.io/plotsquared/api/api-documentation), [PlotSquared membership tiers](https://intellectualsites.gitbook.io/plotsquared/features/plot-membership-tiers).
- Use WorldGuard for spawn, hub, NPC/exhibition hall, and system-region protection because WorldGuard supports Bukkit/Paper servers, WorldEdit-defined regions, and region flags. Sources: [WorldGuard installation requirements](https://worldguard.enginehub.org/en/latest/install/#requirements), [WorldGuard region quick start](https://worldguard.enginehub.org/en/latest/regions/quick-start/), [WorldGuard flags](https://worldguard.enginehub.org/en/latest/regions/flags/).
- Use FAWE instead of WorldEdit only if the team needs higher-volume paste operations and has validated plugin compatibility with the pinned Paper version. This recommendation follows from FAWE's direct-replacement warning, supported-region-plugin list, and asynchronous-operation guidance. Sources: [FAWE installation](https://intellectualsites.gitbook.io/fastasyncworldedit/getting-started/installation), [FAWE API usage](https://intellectualsites.gitbook.io/fastasyncworldedit/api/api-usage).
- Use Multiverse-Core for conventional multi-world loading and navigation unless People-map cloning requires a specialized world format. This recommendation follows from Multiverse-Core's stated purpose as a Bukkit multi-world management solution. Source: [Multiverse-Core GitHub README](https://github.com/Multiverse/Multiverse-Core).
- Use Citizens for the three category NPCs if player-like NPCs are required; use Paper display/interaction entities if static click targets are sufficient. This recommendation follows from Citizens' documented Paper/Spigot NPC role and Paper's display entity API availability. Sources: [Citizens official site](https://www.citizensnpcs.co/), [Paper display entities](https://docs.papermc.io/paper/dev/display-entities/).
- Use LuckPerms for staff/student role permissions because LuckPerms is a permissions plugin with a documented developer API. Sources: [LuckPerms permissions](https://luckperms.net/wiki/Permissions), [LuckPerms Developer API](https://luckperms.net/wiki/Developer-API).
- Use CoreProtect for independent block/action logging and rollback evidence, and separately record competition-domain audit events in the Hill175 backend. This recommendation follows from CoreProtect's documented lookup, rollback, restore, and custom block-change logging API. Source: [CoreProtect API documentation](https://docs.coreprotect.net/api/).

### People private map cloning

- Treat People entries as clones of a bounded, cropped campus template rather than unbounded worlds. This recommendation follows from the operational costs of world load/unload and from the availability of Bukkit/Paper world lifecycle APIs and Slime-World-Manager clone commands. Sources: [Paper `createWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#createWorld(org.bukkit.WorldCreator)), [Paper `unloadWorld`](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)), [Slime-World-Manager clone command](https://github.com/cijaaimee/Slime-World-Manager/blob/develop/.docs/usage/commands-and-permissions.md).
- Prototype conventional folder-copy world cloning first, then evaluate AdvancedSlimePaper/SlimeWorldManager if the conventional approach cannot support expected People-world count and load latency. This recommendation follows from the fact that AdvancedSlimePaper is a fork/custom world-format stack suitable for per-player worlds, which creates deeper platform coupling than standard Bukkit/Paper world APIs. Sources: [InfernalSuite AdvancedSlimePaper description](https://infernalsuite.com/), [Paper world lifecycle APIs](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html).
- Never load or unload private worlds mid-tick; schedule world lifecycle work outside active tick-world phases. This recommendation follows from Paper's Javadocs warning about mid-tick world load/unload side effects. Source: [Paper `unloadWorld` Javadocs](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html#unloadWorld(org.bukkit.World,boolean)).

### Capture pipeline

- Treat the in-game camera item as a pose recorder, not as an actual screenshot tool. This recommendation follows from the absence of a Paper API for client framebuffer capture and from the existence of server/browser-renderer alternatives. Sources: [Paper API guide](https://docs.papermc.io/paper/dev/api/), [Prismarine Viewer headless](https://github.com/PrismarineJS/prismarine-viewer#headless), [BlueMap webapp start-location](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/configs/Webapp.md#start-location).
- Use a dedicated capture account/client or web renderer for final images. This recommendation follows from Prismarine Viewer's headless bot-view rendering support and BlueMap's webapp camera-anchor support. Sources: [Prismarine Viewer headless](https://github.com/PrismarineJS/prismarine-viewer#headless), [BlueMap webapp start-location](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/configs/Webapp.md#start-location).
- Prototype two capture backends: BlueMap plus Playwright browser screenshots for map-like consistent renders, and Mineflayer plus Prismarine Viewer for bot-position renders. This recommendation follows from BlueMap's web map/start-location features and Prismarine Viewer's Mineflayer/headless modes. Sources: [BlueMap webapp config](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/configs/Webapp.md), [Prismarine Viewer README](https://github.com/PrismarineJS/prismarine-viewer).
- Reserve ReplayMod/ReplayStudio for archival video experiments rather than first-pass voting images. This recommendation follows from ReplayMod being a client mod and ReplayStudio handling replay packet dumps rather than being a simple server-side screenshot API. Sources: [ReplayMod README](https://github.com/replaymod/replaymod), [ReplayStudio README](https://github.com/ReplayMod/ReplayStudio).

### Launcher and client distribution

- Do not commit, host, or distribute Minecraft client JARs, assets, patched game files, or modded client/server versions in the Hill repository or launcher bundle. This recommendation follows directly from the Minecraft EULA's distribution restrictions. Source: [Minecraft EULA distribution restrictions](https://www.minecraft.net/en-us/eula#what-you-can-and-cant-do-with-minecraft-software-and-content).
- If a launcher/helper is built, make it a configuration and launch wrapper around a legitimately installed or officially downloaded Minecraft installation rather than a package containing copied game files. This recommendation follows from the EULA's distinction between buying/downloading/installing/playing and redistributing Mojang/Microsoft-made software. Source: [Minecraft EULA](https://www.minecraft.net/en-us/eula).
- Add the official Minecraft disclaimer to the competition website, launcher page, and public materials. This recommendation follows from the Minecraft Usage Guidelines disclaimer requirement. Source: [Minecraft Usage Guidelines essential requirements](https://www.minecraft.net/en-us/usage-guidelines#essential-requirements).
- Require Hill/legal/IT review before relying on offline-mode access for users without genuine paid-for Minecraft because the Usage Guidelines say server access must only be granted to users with a genuine paid-for version. Source: [Minecraft Usage Guidelines servers and hosting](https://www.minecraft.net/en-us/usage-guidelines#servers-and-hosting).

### Map generation and sourcing

- Use Arnis as a first-pass campus voxelization/reference generator, not as final architectural truth. This recommendation follows from Arnis' use of OpenStreetMap/elevation data and the likely gap between public geospatial data and accurate campus architecture. Sources: [Arnis GitHub README](https://github.com/louis-e/arnis), [OpenStreetMap wiki: Arnis](https://wiki.openstreetmap.org/wiki/Arnis).
- Preserve OpenStreetMap attribution anywhere OSM-derived campus maps, renders, or data-derived outputs are published. This recommendation follows from OSM's attribution and ODbL notice requirements. Source: [OpenStreetMap copyright](https://www.openstreetmap.org/copyright).
- Use WorldPainter for staff-authored terrain cleanup and repeatable exports when hand-authoring the campus crop or category landscapes. This recommendation follows from WorldPainter's scripting API support for exporting Minecraft maps and loading custom terrain/layers. Source: [WorldPainter scripting API](https://www.worldpainter.net/trac/wiki/Scripting/API).
- Prefer a custom Hill-themed spawn/exhibition hall build over a downloaded lobby map. This recommendation follows from Minecraft event/brand constraints and third-party map-license uncertainty. Sources: [Minecraft Usage Guidelines live events](https://www.minecraft.net/en-us/usage-guidelines#live-in-game-events), [Planet Minecraft Terms of Use](https://www.planetminecraft.com/terms_of_use/).
- If any marketplace or community map is used, record the source URL, author, license/EULA, permitted use, modification rights, attribution requirement, redistribution limits, and a saved copy of the terms at acquisition time. This recommendation follows from Planet Minecraft's general redistribution restriction and BuiltByBit's resource-specific EULA structure. Sources: [Planet Minecraft Terms of Use](https://www.planetminecraft.com/terms_of_use/), [BuiltByBit resource EULAs](https://builtbybit.com/wiki/resource-eulas/).

## Open implementation risks

- Offline-mode identity is a security risk unless every connection is gated by Hill175 authentication before gameplay access. This risk follows from Paper's account-authentication boundary and Velocity's offline-backend impersonation warning. Sources: [Paper `online-mode`](https://docs.papermc.io/paper/reference/server-properties/#online-mode), [Velocity security overview](https://docs.papermc.io/velocity/security/#securing-your-servers).
- The launcher requirement conflicts with Minecraft client redistribution rules if it includes copied Minecraft-owned JARs or assets. This risk follows from Minecraft's EULA distribution restrictions. Source: [Minecraft EULA distribution restrictions](https://www.minecraft.net/en-us/eula#what-you-can-and-cant-do-with-minecraft-software-and-content).
- Paper Dialog API adoption is version-sensitive. This risk follows from Paper's Dialog API page being written for 1.21.8 and warning about missing/incomplete support in older versions. Source: [Paper Dialog API version note](https://docs.papermc.io/paper/dev/dialogs/#dialog-api).
- Private People-world cloning may become the highest operational-risk subsystem because standard Bukkit/Paper world lifecycle APIs exist but specialized per-player-world formats imply platform coupling. Sources: [Paper world lifecycle APIs](https://jd.papermc.io/paper/26.2/org/bukkit/Server.html), [InfernalSuite AdvancedSlimePaper description](https://infernalsuite.com/).
- Voting images require a separate capture/render system because the Paper plugin cannot directly capture each student's local rendered screenshot. Sources: [Paper API guide](https://docs.papermc.io/paper/dev/api/), [Prismarine Viewer headless](https://github.com/PrismarineJS/prismarine-viewer#headless), [BlueMap webapp start-location](https://github.com/BlueMap-Minecraft/BlueMapWiki/blob/master/wiki/configs/Webapp.md#start-location).
