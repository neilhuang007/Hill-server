Verified: 2026-08-31. Scope: primary MapSmith/Arnis public docs/source plus local Hill-server artifacts under `runtime/`; no production state inspected or changed.

- Arnis-generated Java worlds under `runtime/campus-reconstruction/arnis-baseline-core/Arnis World 1/` and `runtime/campus-reconstruction/arnis-hires-core/Arnis World 1/`. MapSmith’s official page says it converts real-world data/elevation into Java or Bedrock Minecraft worlds and is “Powered by Arnis.” ([MapSmith official page](https://arnismc.com/mapsmith/), [Arnis README](https://github.com/louis-e/arnis))
- Historical local GIS/LiDAR structures under `runtime/campus-output/hill-campus-*`, generated by this repo’s `scripts/generate-hill-campus.py`. These are not proven MapSmith exports; their manifests explicitly say they are generated from GIS, DEM, lidar, and OSM, and that VoxelEarth was only used for interactive inspection. ([phase-1 manifest](../../runtime/campus-output/hill-campus-phase1-manifest.json), [generator](../../scripts/generate-hill-campus.py))
- `structure (1).nbt`, a staged/untracked structure with a rich 178-state palette but no local provenance manifest found in this audit. Treat it as unusable for production until provenance is documented.

MapSmith/Arnis-style building shells are technically compositable onto VoxelEarth terrain, but not by copying a whole generated world or whole structure. The safe path is to extract only shell/facade/roof/window blocks, transform coordinates into the VoxelEarth world coordinate frame, rescale from the source world’s metres-per-block, and paste after collision/height QA. Direct overlay is a correctness risk because the local VoxelEarth final world uses a VoxelEarth Java 3D Tiles coordinate pipeline at `2.1` blocks/metre, while the local GIS structures use `1.0` metre/block and the latest chapel prototype uses `2.0` blocks/metre. ([world manifest](../../server-assets/worlds.yml), [VoxelEarth full manifest](../../runtime/campus-reconstruction/voxelearth-server-smoke/hill_school_voxelearth_full_20260830_2207/voxelearth-hill-manifest.json), [chapel manifest](../../runtime/campus-reconstruction/voxelearth-proof/open-data-chapel/manifest.json))

## Primary MapSmith/Arnis evidence

MapSmith is the Arnis-hosted browser generation service. Its official page says it converts real-world data and elevation into playable Minecraft worlds, lets the user draw a custom area, choose Java or Bedrock, and notes that generation detail depends on OpenStreetMap mapping quality. The page also says MapSmith is powered by Arnis. ([MapSmith official page](https://arnismc.com/mapsmith/))

Arnis itself describes the engine as creating Minecraft Java/Bedrock worlds from real-world geography, topography, and architecture, processing OpenStreetMap plus elevation data. Its README documents generation modes: `geo-terrain` creates buildings, roads, and other OSM objects on real elevation terrain; `geo-only` puts OSM objects on flat ground; `terrain-only` omits objects. ([Arnis README](https://github.com/louis-e/arnis#arnis))

The Arnis building source supports richer clean building shells than the current VoxelEarth chapel prototype:

- Building categories include religious/church/chapel handling and separate wall palettes for residential, commercial, industrial, religious, institutional, historic, garage, shed, greenhouse, and other classes. ([Arnis `buildings.rs`](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L117-L194), [category logic](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L333-L390))
- Roof logic reads `roof:shape` and maps common gabled/hipped/mansard/gambrel/skillion/pyramidal/dome/cone/onion forms instead of treating every building as a flat block. ([roof parser](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L965-L971), [roof type mapping](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L6021-L6042))
- Facade planning classifies street-facing, party, open, rear, and corner facades from local road/building masks, then style resolution feeds wall, floor, window, accent, roof, door, parapet, and wall-depth choices into the building config. ([facade plan](https://github.com/louis-e/arnis/blob/main/src/element_processing/building_facade.rs#L190-L293), [style resolution](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L6339-L6372), [building config](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L6446-L6474))
- Religious facade depth includes buttress/cornice behavior, which is directly relevant to chapel-like shells. ([religious buttress code](https://github.com/louis-e/arnis/blob/main/src/element_processing/buildings.rs#L5617-L5677))

Important limitation: the public MapSmith page proves the hosted service is Arnis-powered, not the exact engine commit or feature flags used for any downloaded MapSmith job. Use the Arnis source as the closest primary technical source for MapSmith behavior, not as proof of a specific MapSmith output’s provenance or parameters.

## Can MapSmith/Arnis shells be composited onto VoxelEarth terrain?

Yes in principle, but only with a dedicated extraction/transform/composite pass. The safe compositing target is VoxelEarth terrain/world data; the safe compositing source is shell/facade/roof/window blocks from a known-provenance Arnis/MapSmith or local GIS structure. Do not paste a complete MapSmith/Arnis world over VoxelEarth, because that would replace terrain, roads, and possibly dimensions/chunks that the VoxelEarth QA already validated.

Required correctness steps:

1. Prove provenance and license for the shell source. The internal implementation plan already requires documented source-data and derivative-use rights for MapSmith/VoxelEarth-derived People assets. ([implementation plan](../HILL_175_IMPLEMENTATION_PLAN.md))
2. Extract only shell states. For local GIS structures, start with known shell states (`bricks`, `stone_bricks`, `deepslate_tiles`, `glass`, selected air cutouts) and exclude terrain, water, roads, fields, trees, and broad fill. For Arnis worlds, parse `.mca` chunks and classify building/facade states more carefully because the palette is broad and includes terrain/decorative/interior blocks.
3. Normalize coordinates. Local GIS structures use a UTM/EPSG:26918-like local grid with `1.0` m/block. The VoxelEarth chapel prototype records EPSG:26918 with `+easting`, `+elevation`, `-northing`, which is compatible in direction but not scale. The final VoxelEarth full world records `+X east, +Y up, +Z south` and an ECEF-origin pipeline, so a reproducible UTM/WGS84-to-final-world transform must be implemented and tested against multiple landmarks.
4. Normalize scale. Local GIS structures are 1 block/m; Arnis hires is 2 blocks/m; chapel prototype is 2 blocks/m; final VoxelEarth is 2.1 blocks/m. A direct integer copy from any one source will drift unless resampled.
5. Resolve vertical alignment. The local GIS chapel height is 10.67 m, while the latest VoxelEarth solid chapel output is 14.5 m tall after solidification and the point-cloud source span is 18.66 m. This is a material correctness issue: either the local shell is too short, the VoxelEarth solid includes tower/roof/vegetation artifacts, or both. Validate against the chapel before compositing the whole campus.
6. Resolve footprint alignment. Local GIS chapel footprint is 431 cells at 1 m/block. The VoxelEarth solid chapel has 2,370 projection columns at 0.25 m²/column, about 592.5 m². That is roughly 37.5% larger than the local structure footprint, likely from buffered input, roof overhang, segmentation spread, or differing footprint definitions.
7. Run local BlueMap QA on a clone, not production. Verify chapel, academic core, dorm clusters, and athletic buildings from top-down and oblique views before accepting a composite.

## Practical recommendation

Use MapSmith/Arnis output as a design reference and possible shell donor only after provenance is explicit. For implementation, the least risky path is:

1. Build a deterministic shell-extractor for the local GIS structure first, because its manifest, scale, and chapel semantics are already known.
2. Composite one landmark only: chapel shell/facade/roof/window blocks onto a cloned VoxelEarth campus.
3. Validate transform/scale/height in BlueMap against the latest VoxelEarth chapel prototype and official/local reference imagery.
4. Only after chapel alignment passes, generalize to other campus buildings.

Do not use `structure (1).nbt` or any MapSmith download as a production source until the file is tied to a source run, parameters, rights, and expected coordinate frame.
